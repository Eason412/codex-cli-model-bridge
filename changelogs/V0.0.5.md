# V0.0.5（未发布）

## 变更

- `sync` 改为从 CPA 拉取 Codex 格式的实时模型列表（带本机 Codex 版本号），整份生成模型目录，不再读取会过期的 `models_cache.json`。新模型随 CPA 升级进入列表，下一次同步即出现在 Codex，不需要改代码或写清单。
- 个人偏好改为 `overrides.json`：键为精确 ID 或通配符，只写与上游不同的字段，`null` 删除字段；未匹配的键只报告不阻断。
- `models.d` 只用于补充 Codex 格式列表里没有的路由；`template_slug` 改为可选，同名模型出现在实时列表后清单自动让位并在回执中列出。
- 桌面透明模式经 `openai_base_url` 同步，由代理补认证；目标目录默认取所用配置的 `model_catalog_json`，相对路径按配置文件所在目录解析（`audit`、`probe` 同样）。
- `audit` 新增 `codex_load_error` 和 `in_sync_with_live_list`：前者用 Codex 自己的解析器检查当前目录，后者检查目录是否落后于实时列表。
- 回执和 `audit` 中的地址去掉用户名、密码和查询参数；Codex 解析错误中的取值被遮蔽，只保留字段名和位置。

## 文档

- README 改为写给读者的介绍：特点、工作原理、交给 agent 设置的方式和 PR 注意事项；新增英文版 `README.en.md`。
- 新增 `SETUP.md`：写给 Claude Code、Codex、Gemini CLI 等 agent 的分步安装手册，每步有成功条件，并列出需要先征求用户同意的操作。

## 安全条件

- 写入前用 `codex debug models`（不联网）加载候选目录，Codex 不接受或读到的模型集合不一致时不写入。
- 实时列表失败或为空、个人偏好或补充清单不合法（含重复 ID）、补充路由缺失、配置的 `model`、`review_model`、`[agents].default_subagent_model` 缺失，或 `[profiles.*]`、子代理角色 `config_file` 使用的模型会被移除时，不写入。
- 只同步本工具的路由：`openai_base_url` 不是透明代理（如 Router）或活动 Provider 不是 `cli_proxy` 时拒绝。
- 内容不变不改文件；有变化时只保留一份 `<目录>.previous`，且只有 Codex 能加载的旧目录才会成为这份副本；现有目录损坏或 Codex 读不了时直接重建，不覆盖 `.previous`，此时以 `.previous` 判断受保护的模型。

## 移除

- 仓库内置的 7 个模型清单和 `policies/catalog.json`；仓库不再写任何模型 ID。
- `sync` 的 `--native-catalog`、`--catalog-policy`、`--models`、`--enabled-manifests`、`--adopt`、`--prune-managed`、`--skip-live-check`，以及 `supersedes` 字段和归属状态。

## 升级说明

- 旧的 `catalog-policy.json`、`enabled-manifests.json`、`state.json` 不再读取，回执的 `legacy_files_ignored` 会列出它们。原 `hidden_native_model_ids` 改写为 `overrides.json` 中的 `{"<id>": {"visibility": "hide"}}`。
- 已在实时列表中的模型，其 `models.d` 清单被忽略；仍需要的差异移到 `overrides.json`。
- 统一上下文大小改用 Codex 的 `model_context_window`。

## 验证

- 70 项 Python 测试通过，覆盖实时列表失败、Codex 拒绝候选目录或旧目录、路由归属（含 localhost 等价）、配置模型保护、重复清单、损坏目录重建、精确 ID 与通配符、相对路径、错误信息与地址脱敏。
- 经两轮 Codex（gpt-6.1-sol）与 Sonnet 独立审查，发现的问题均已修复并补充回归测试。
- 本机实测：经 8318 同步 14 个模型，Codex 解析通过；`gpt-6-astra`、`gpt-6.1-sol` 的 `probe --desktop --shell` 通过；`model_context_window = 500000` 下会话记录的有效窗口为 475000。

## 已知限制

- CPA 刚重启、账号尚未加载完时，实时列表可能暂时变短；这仍是可用目录，缺的模型在下一次同步时恢复。
- 第三方上游（Kimi、DeepSeek、GLM 等）在 CPA Codex 格式列表中的元数据未逐一实测，需要时用 `overrides.json` 修正。
